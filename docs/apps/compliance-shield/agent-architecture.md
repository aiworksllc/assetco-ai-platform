# ComplianceShield — Agent Architecture

**Application:** ComplianceShield
**Agents:** 4 (trade-surveiller, position-reporter, breach-detector, regulatory-filer)
**Architecture principle:** Observe everything. Remediate nothing.

---

## Overview

ComplianceShield agents operate as a one-way mirror into AssetCo's AI operations. They have the broadest read access of any agents in the firm — by design — but the most constrained write access. The surveillance mandate requires visibility into everything. The separation-of-duties mandate requires that observation never bleeds into action.

All four agents are governed by Sentinel-Ops SOE enforcement. Every read and every write is logged to the immutable Chronicle audit trail.

---

## Agent: trade-surveiller

**Role:** Real-time trade surveillance across all firm AI agents and applications.

**Surveillance scope — broadest read access in the firm.** trade-surveiller monitors all trading activity across:
- TradeSentinel (order generation, execution, blotter)
- AlphaEngine (algorithmic order generation, strategy signals)
- OpsFabric (settlement instructions, trade confirmation, post-trade processing)

This cross-application read scope is intentional and necessary. Spoofing and layering patterns can only be detected when order placement data (TradeSentinel) is correlated against execution data (OpsFabric) and strategy signals (AlphaEngine). Siloed surveillance would miss cross-system patterns.

**Detection patterns:**

- **Spoofing:** Monitors for rapid order placement and cancellation sequences. Trigger condition: >60% of orders at a given price level cancelled within 500ms of placement, with net directional price impact consistent with the remaining live orders. Generates STR candidate file for human compliance review — does not cancel orders.

- **Wash trading:** Cross-references buy and sell orders where beneficial ownership traces to the same AssetCo entity (fund, account, sleeve). Configurable time window (default: same trading day). Flags sequences where both legs of a round-trip are present with no economic rationale.

- **Layering:** Monitors for stacked order book construction — multiple orders at incrementally worse price levels placed in sequence, then cancelled as price moves toward the stacked side. Statistical signature: order placement rate at ≥3 consecutive price levels, >80% cancellation rate on those orders within 2 minutes of placement.

- **Front-running:** Compares ResearchNexus research publication timestamps against TradeSentinel execution timestamps. Flags any trade in the same instrument executed within 30 minutes prior to research report distribution. Cross-references the trading agent's identity against the list of agents with pre-publication research access.

- **Suitability validation:** For every client-directed order generated by AlphaEngine, verifies that a suitability determination record exists in the client profile store for the relevant account and instrument class. Flags orders where documentation is absent or expired (>12 months old for non-discretionary accounts).

**Write access:** `compliance/surveillance/**` only. Writes alert files and STR candidate records. Zero write access to any trading system, order management system, or position store.

**Tool restrictions:** alert generation tools allowed. Any tool that could interact with a trading system (order cancellation, position modification, strategy parameter adjustment) is denied at the SOE gate.

## Agent: position-reporter

**Role:** Generates daily, weekly, monthly, and quarterly regulatory position reports.

**Data sources:**
- OpsFabric position store (end-of-day positions, intraday snapshots)
- TradeSentinel execution records (for transaction-level reporting)
- RiskCompass counterparty data and netting set information (for EMIR bilateral netting)
- Fund registry (LEI codes, fund identifiers, classification)

**Report types generated:**

- **EMIR Trade Repository (daily):** OTC derivative position reports in ESMA ISO 20022 XML format. Includes UTI (Unique Trade Identifier), LEI codes for both counterparties, notional amounts, mark-to-market valuations, and collateral data. Generated by 18:00 UTC for same-day submission window.

- **MiFIR RTS 25 (T+1):** Transaction reports for all instruments in scope (equities, bonds, derivatives admitted to trading on EU regulated markets, MTFs, OTFs). Includes executing entity LEI, buyer/seller LEI, instrument ISIN, quantity, price, venue, and execution timestamp. Generated by 07:00 local time the following trading day.

- **CFTC large trader (daily):** Aggregated position reports for futures and options positions exceeding CFTC reporting thresholds. Formatted per CFTC Form 40 specification.

- **SEC 13F (quarterly):** Long equity positions exceeding $100M AUM threshold. Aggregated across all funds and accounts managed by AssetCo. Generated within 45 days of quarter-end.

- **FINRA FOCUS (monthly):** Financial and operational combined uniform single report. Pulls capital, revenue, and operational data from OpsFabric.

**Write access:** `compliance/reports/positions/**` only. Reads from position systems; writes only to designated report directories. Cannot modify source position data.

**Tool restrictions:** report generation and file formatting tools allowed. No access to position modification, trade booking, or client record tools.

## Agent: breach-detector

**Role:** Monitors SOE violation logs, risk limit breaches, information barrier violations, and unauthorized access patterns. Escalates to human compliance officers. Does not remediate.

**Monitoring sources:**
- Sentinel-Ops SOE audit logs (all 25 managed agents)
- RiskCompass risk alert feed (position limit breaches, VaR limit breaches, concentration limit breaches)
- Information barrier crossing attempt logs (tagged by the SOE gate when an agent attempts to access MNPI-classified data)
- Unauthorized data access pattern logs (SOE DENY decisions for data access outside defined SOE scope)
- OpsFabric access logs (settlements agent access to non-assigned trade records)

**Alert classification:**

| Severity | Definition | Response SLA | Notification |
|---|---|---|---|
| CRITICAL | Active information barrier violation, regulatory deadline breach, or unauthorized data modification attempt | 60 seconds | CCO + designated compliance officer + Slack #compliance-critical |
| HIGH | Repeated SOE violations by a single agent (>3 in 1 hour), limit breach exceeding 110% of threshold | Same day | CCO + compliance officer |
| MEDIUM | Single SOE violation, limit breach within threshold, suitability gap | Next business day | Compliance officer |
| LOW | Pattern anomaly with no confirmed violation, approaching-threshold alerts | Weekly review | Compliance team digest |

**Separation of duties — enforced at SOE layer:**
- breach-detector CANNOT modify SOE definitions
- breach-detector CANNOT block or terminate any agent
- breach-detector CANNOT modify risk limits in RiskCompass
- breach-detector CANNOT update client records or positions
- All enforcement authority rests with human compliance officers

breach-detector's role is to be the fastest, most accurate compliance analyst in the room — not to replace the compliance officer's judgment.

**Write access:** `compliance/alerts/**` and `compliance/escalations/**` only.

**Tool restrictions:** notification and escalation tools allowed (Slack, email notification pipeline). All remediation tools (SOE modification, agent termination, data modification) denied.

## Agent: regulatory-filer

**Role:** Formats and prepares regulatory submissions from ComplianceShield report outputs. All submissions require human sign-off before filing.

**Filing pipeline:**

1. position-reporter generates source reports to `compliance/reports/positions/**`
2. regulatory-filer reads source reports, applies filing-specific formatting and validation
3. Formatted submission written to `compliance/filings/**` with status DRAFT
4. Validation checks run (field completeness, schema compliance, threshold checks)
5. Status updated to PENDING_REVIEW; CCO or designated officer notified
6. Human reviews, approves (status → APPROVED), or returns with annotations
7. Human submits via regulatory portal; regulatory-filer updates status to SUBMITTED on confirmation

**Filing formats supported:**
- EMIR TR (daily) — DTCC GTR and REGIS-TR XML schemas
- MiFIR RTS 25 (T+1) — ESMA TRACE submission format
- Form PF (quarterly) — SEC EDGAR XML
- SEC 13F (quarterly) — SEC EDGAR XBRL
- FINRA FOCUS (monthly) — FINRA Web FOCUS submission format
- FINRA Rule 3110 supervision report (annual) — internal format for CCO attestation

**Write access:** `compliance/filings/**` ONLY. Reads from `compliance/reports/**` and `compliance/surveillance/**`. Cannot write anywhere outside the filings directory. Cannot modify source reports, trading data, positions, or client records.

**Tool restrictions:** file generation and formatting tools allowed. Submission tools (direct API calls to regulatory portals) are denied — humans submit. This is not a policy preference; it is an SOE hard deny.

## Cross-Agent Data Flow

```
All trading events (TradeSentinel, AlphaEngine, OpsFabric)
         |
         v
  trade-surveiller ──────────────> compliance/surveillance/alerts/
         |
         v
  position-reporter ─────────────> compliance/reports/positions/
         |
         v
  regulatory-filer ──────────────> compliance/filings/ (DRAFT → PENDING_REVIEW)
                                          |
                                          v
                               Human CCO review → APPROVED → Human submits

SOE audit logs + RiskCompass alerts + IB crossing logs
         |
         v
  breach-detector ───────────────> compliance/alerts/ + compliance/escalations/
                                          |
                                          v
                               CCO David Okonkwo + compliance officers
```

No agent writes to any source system. Data flows are unidirectional from trading systems into the compliance reporting layer.
